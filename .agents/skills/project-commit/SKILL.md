# 项目自动提交

遵守[全局约束](../../../AGENTS.md)。项目已有自动提交授权，无需再次确认；复用本任务已完成的验证，不展开完整测试流程。

## 执行

1. 查看当前分支、工作区、暂存与未暂存差异，确认本任务范围；有事实变化时先使用[文档同步技能](../project-doc-sync/SKILL.md)。验证与文档同步已完成且内容未变时直接复用结果。
2. 按独立目的拆分提交，每组保持可解释；同一目的的实现和文档一起提交。只暂存本任务文件或可安全分离的改动，不使用无范围的全量暂存，不纳入密钥、依赖或临时产物。
3. 标题采用 `类型(可选范围): 中文简述`，如 `feat: 实现角色移动`；正文简述背景、关键选择及理由、必要取舍、实现结果和实际验证。无关内容不混合，不复制对话，不虚构检查结果。
4. 复核该组差异与必要检查后提交；没有改动就跳过空提交。存在无关暂存内容且任务文件可按路径区分时，使用 `git commit --only -- <任务路径>` 并附上提交说明，不执行无路径限制的提交；同文件混杂且无法安全拆分时保留并报告，不强行提交或取消他人暂存。
5. 默认在 `main` 开发并提交，无需为提交新建分支。若使用本任务创建或确认完全属于本任务的临时分支，提交后安全切回 `main`，使用 `git merge --ff-only` 合并，成功后用 `git branch -d` 删除该临时分支。
6. 确认提交内容、当前分支和剩余差异，简要报告提交号与实际检查结果。无法安全切换、合并或判定分支归属时保留成果并说明原因，不删除未合并内容，不强制重置或改写历史，不自动推送、创建 PR 或处理无关分支。

本技能直接完成项目本地流程，不再层层调用用户级提交、分支或维护技能。
