# 项目提交与主分支同步

遵守[全局约束](../../../AGENTS.md)。项目已有自动提交与主分支普通推送授权，无需再次确认；仅对游戏改动做必要运行验证，文档与技能不执行格式检查、校验或测试。

## 执行

1. 任务开始时查看当前分支、工作区及暂存状态，按下方同步规则获取远程 `main` 并安全同步，随后确认本任务范围；提交前查看差异，有事实变化时使用[文档同步技能](../project-doc-sync/SKILL.md)。已有上下文与运行结果可直接复用。
2. 按独立目的拆分提交，每组保持可解释；同一目的的实现和文档一起提交。只暂存本任务文件或可安全分离的改动，不使用无范围的全量暂存，不纳入密钥、依赖或临时产物。
3. 标题采用 `类型(可选范围): 中文简述`，如 `feat: 实现角色移动`；正文简述背景、关键选择及理由、必要取舍、实现结果和实际验证。无关内容不混合，不复制对话，不虚构检查结果。
4. 确认该组改动范围后提交，不为文档、技能或格式类改动执行检查或测试；没有改动就跳过空提交。存在无关暂存内容且任务文件可按路径区分时，使用 `git commit --only -- <任务路径>` 并附上提交说明，不执行无路径限制的提交；同文件混杂且无法安全拆分时保留并报告，不强行提交或取消他人暂存。
5. 默认在 `main` 开发并提交，无需为提交新建分支。若使用本任务创建或确认完全属于本任务的临时分支，提交后先获取远程最新状态，安全切回干净的 `main` 并快进同步远程，再使用 `git merge --ff-only` 合并本任务分支；成功后用 `git branch -d` 删除该临时分支，无法快进时保留成果与分支并报告。
6. 每个独立提交归入本地 `main` 后，按下方规则自动推送并核对远程；不能因没有新改动而跳过已有未推送提交的同步。最终报告提交号、实际检查结果和两端同步状态，不创建 PR 或处理无关分支。

## 主分支同步

- 使用项目已配置的 `origin`；任务开始时执行 `git fetch origin`，每次提交或临时分支收尾后、推送前必须再次获取最新远程状态，不能复用任务开始时的远程判断。不修改远程地址或认证配置。
- 在 `main` 上比较本地与 `origin/main`：本地仅落后且工作区干净时，用 `git merge --ff-only origin/main` 同步；本地仅领先时保留提交，准备普通推送；相同时直接继续。存在未完成改动时不擅自暂存、隐藏或丢弃它们来切换或合并。
- 推送前检查 `origin/main..main` 中的全部提交；远程尚无 `main` 时检查本地 `main` 历史，确认均为本项目已授权成果后再推送。已核对的提交无变化时复用结论；来源不明的提交保留并报告，不擅自发布。
- 两端可安全快进同步后，使用 `git push -u origin main` 推送本地 `main`，建立或保持跟踪关系；只有获取远程成功且确认尚无 `main` 时，才用同一命令首次创建。只推送 `main`，不发布临时分支。
- 推送成功后比较 `git rev-parse main` 与 `git ls-remote --heads origin main` 的实际提交号；一致才报告已同步，不能只依赖本地的远程跟踪引用。
- 网络、权限、推送拒绝、两端分叉或无法安全切换、合并时，保留所有成果并明确报告未同步状态及原因；不强制推送、重置、变基或删除未合并提交，不无限重试。

本技能直接完成项目提交与同步流程，不再层层调用用户级提交、分支或维护技能。
