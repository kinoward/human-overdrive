## 开发顺序

1. 确定最小玩法范围与演示标准，记录到[产品规格](../产品/产品规格.md)。
2. 选定技术并建立可运行入口，更新[架构地图](../架构/架构地图.md)和[实际命令](../规范/开发流程.md#实际命令)。
3. 按独立功能实现核心循环，完成必要验证并持续提交。
4. 仅在核心循环可演示后处理必要体验问题，预留最终试玩与交付时间。

这是执行顺序，不代表功能已完成，也不预设具体时间分配或额外功能。
