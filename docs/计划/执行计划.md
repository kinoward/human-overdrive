# 执行计划

[返回文档地图](../MAP.md)

## 当前主线

本项目全部采用 Three.js + Rapier + TypeScript + Vite。本轮仅确定方向与清理方案说明，已停止实现和资源接入；以下缺口作为后续任务保留，不在本轮执行。

## 已完成

- 已实现真实北四环水平 GIS 数据、程序化场景、汽车与摩托街机控制、普通交通、五级追捕、里程和失败判定。
- 已实现城市选择与预告、双车型车库、昵称、指南、驾驶 HUD、暂停与重开、结算、本机最近 100 局成绩及计时／车技双榜。
- 已取得 Poly Haven CC0 的沥青、混凝土贴图和日落 HDR，以及开放中文字体，当前源文件位于 `public/assets/art/`；尚未被网页代码加载。
- 已在 Chrome 核对 14 个赞助平台，记录[资产制作建议](../调研/赞助资源与资产制作.md)、WorldGen 边界、首批清单与提示词；本轮未生成或接入资产，制作顺序仍是建议。
- 此前 `npm run build` 通过；Chrome 手动确认过城市与选车、两车型加速、汽车转向、近失得分、警告升级至三级及相应警车／直升机、暂停继续、摩托碰撞翻车、结算分项、双榜过滤和刷新保存。

## 当前待处理

- 尚未人工跑完完整 5 公里、最高 10 警车与 3 直升机下的 10 星通关、围堵失败及全部主辅路连接；不能把这些路径写成已验证通过。
- 当前只对路外停止计里程，尚未用实体边界完整禁止驶出道路或穿越主辅路隔离带。
- 车辆、交通、警车、直升机与城市仍是程序化示意外观；完整视觉车损尚未实现，也没有接入外部 GLB／glTF 模型。
- 已准备的道路材质、HDR 和字体尚未接入渲染流程；接入后需要在实际 Chrome 入口确认加载时间、内存和运行流畅度。
- 包含物理 WebAssembly 的现有主包约 4.95 MB；最终包体会随模型与贴图变化，尚未做定量性能测量。

## 后续顺序

1. 为道路生成米制 UV，接入现有路面材质与 HDR，建立一辆车和一段道路的网页美术基准；以实际 Chrome 表现决定贴图尺寸、模型复杂度和同时显示数量。
2. 补齐连续可驾驶边界与主辅路隔离带碰撞，只允许从真实连接口切换道路。
3. 用当前最终入口人工跑完完整 5 公里、围堵失败、最高追捕评级和主要道路连接，按实际问题调整驾驶与警力。
4. 按主角车辆、警车、近景路侧设施、少量北京辨识建筑的顺序分批接入成熟或生成的分件 GLB 资产，复用共享材质与重复模块。
5. 在不更换引擎的前提下补充必要视觉车损反馈，并在每批资源接入后体验受影响核心流程。

## 更新方式

只记录已发生的事实、当前缺口与下一步，不将源码提供的功能、文件导入或准备完成写成编译和试玩通过。历史决策通过提交记录追溯。
