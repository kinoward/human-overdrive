## 当前状态

- 已完成：全局约束、Claude Code 专属约束、文档地图体系，以及文档同步与自动提交的项目技能。
- 已完成：相近游戏、引擎、比赛资产资源及 GIS 路线调研；通过问答确认北京精选主辅路、可重复累计里程、街机手感、摩托辅助、围堵失败、2–3 分钟单局与双榜，已记录到[产品规格](../产品/产品规格.md)。
- 已选路线：Three.js + Rapier + TypeScript + Vite；用户要求同步实现游戏外关卡、排行与评分。
- 已接入原型：城市选择与预告、双车型车库、昵称、指南、驾驶 HUD、暂停与重开、结算、本机最近 100 局成绩及计时／车技双榜。
- 已接入原型：真实北四环水平 GIS 数据、程序化场景、车辆与摩托辅助、普通交通、五级追捕、最高 10 警车与 3 直升机、里程和失败判定。
- 已验证：`npm run build` 通过，生产预览在 `http://127.0.0.1:4173` 启动；Chrome 手动确认城市与选车、两车型加速、汽车转向、近失得分、警告升级至三级及相应警车／直升机、暂停与继续、摩托碰撞翻车、结算分项与车技榜。刷新后历史成绩仍在，失败局未进入成功计时榜。
- 已修正：结算返回普通菜单时清理比赛对象；重开释放车辆实例几何与材质；单辆警车靠近不作为围堵；最高压力挑战要求连续有效行驶；汽车键盘与警方转向统一为正确方向。
- 当前交付：可运行的首版原型与本机预览入口，车辆与城市仍为示意外观。
- 下一步：依据用户实际试玩反馈调整驾驶和警力，手动完成完整 5 公里及最高追捕通关，再提高模型和建筑细节。

## 开发顺序

1. 从已保留的生产预览入口收集实际驾驶反馈。
2. 继续人工体验逆行往返、主辅路切换、围堵、完整通关和最高追捕评级，针对实际问题调整。
3. 功能变化后集中编译并体验受影响流程，保持文档和提交同步。
4. 提高资产细节时保留可玩的原型，不用精细模型阻塞后续迭代。

这是执行顺序，不代表功能已完成，也不预设具体时间分配或额外功能。

## 阻塞与未解决问题

- 尚未人工跑完完整 5 公里、最高 10 警车与 3 直升机下的 10 星通关、围堵失败及全部主辅路连接；不能把这些路径写成已验证通过，也未做定量帧率测量。
- 构建通过，但含物理 WebAssembly 的主包约 4.95 MB，存在体积提示；当前本机演示可加载，后续公网发布时再考虑拆分和加载体验。
- 真实 OSM 水平路网已获取；桥高平面化，建筑示意化，复杂立交在空间层级和交通行为上仍有简化。
- 两车型已提供程序化示意外观与街机参数，但没有精细模型或厂商真实年款参数校准。Model 3、Hayabusa 与 Kenney 仍是资产候选，尚未下载接入。
- Tripo、Hyper3D 等赞助权益已核实，但未领取或调用；本地游戏不依赖这些服务。
- 追捕强度、围堵／翻覆阈值、10 星挑战与评分使用首版数值，需要依据实际试玩调整。直升机已跟随与投射搜索灯，广播与完整调度战术尚未实现。
- 排行榜仅在当前浏览器和站点地址保存，非联网竞技榜；跨车型用时不作为已平衡竞技标准。

## 更新方式

仅在目标、进度、下一步或问题确实变化时更新，不为例行提交改写计划。未解决问题只保留问题、影响与下一步；解决后移除当前问题条目，历史原因与处理过程通过提交记录追溯。
