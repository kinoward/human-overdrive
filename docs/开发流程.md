# 开发与维护流程

[返回文档地图](MAP.md)

## 最短工作流程

1. 阅读[文档地图](MAP.md)、[执行计划](执行计划.md)与当前任务对应文档，按[项目提交技能](../.agents/skills/project-commit/SKILL.md#主分支同步)获取并安全同步远程 `main`，检查已有代码和差异，确定本次独立改动的目标；重复操作按[技能地图](技能地图.md)选择已有技能。
2. 按[全局约束](../AGENTS.md)实现当前需求；存在未确认的玩法或交付要求时，先明确需求，不把猜测写成既定事实。
3. 对本次修改执行最小必要验证，修复阻碍核心演示的问题；验证通过且相关内容没有变化时不重复执行。
4. 下表所列事实变化时使用[文档同步技能](../.agents/skills/project-doc-sync/SKILL.md)维护对应文档，再用[项目提交技能](../.agents/skills/project-commit/SKILL.md)自动提交、推送本地 `main` 并确认与 `origin/main` 一致。技能复用已有检查结果，实现符合现有文档时无需改文档；同步失败时如实报告。

## 按改动维护

| 发生的变化 | 必须更新的权威文档 |
| --- | --- |
| 玩法、操作、平台、范围或验收标准改变 | [产品规格](产品规格.md) |
| 技术选型、代码入口、模块职责或依赖改变 | [架构地图](架构地图.md) |
| 任务状态、下一步、阻塞或遗留问题改变 | [执行计划](执行计划.md) |
| 安装、运行、构建、交付或验证方式改变 | 本页“实际命令”及相关流程 |
| 新增、移动或删除文档 | [文档地图](MAP.md)或所属主题页，以及所有受影响引用 |
| 全局约束改变 | [AGENTS.md](../AGENTS.md)，CLAUDE.md 继续仅引用它 |
| 项目技能新增或调整 | [技能地图](技能地图.md)、对应 SKILL.md 及必要的工具入口 |

用户最新要求与既有文档冲突时，以用户要求为准并同步修正文档。规格与代码不一致时，明确区分预期行为、当前实现与缺口；不得通过修改完成状态掩盖未实现功能或未执行验证。

## 实际命令

目前尚无游戏运行环境，安装、启动、构建和交付命令均未建立。技术选型后在此记录已实际验证的命令、必要前置条件与产物位置；不提供推测性命令，也不要求每个任务执行所有命令。项目文档的检查命令统一维护在[文档同步技能](../.agents/skills/project-doc-sync/SKILL.md#文档检查)中。

## 最小验证与交付

- 文档变更：检查事实归属、相对链接和差异，不启动无关构建。
- 游戏变更：按影响选择必要的编译、启动或核心路径试玩；遵守禁止新增测试文件及测试工程的约束。
- 最终交付：使用实际交付方式打开游戏，试玩产品规格约定的核心流程，并确认必要资源可用。
- 未执行或未通过的检查如实写入提交正文；需要后续处理的问题记录到[执行计划](执行计划.md)，不宣称验证已通过。
