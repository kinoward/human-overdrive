# 开发与维护流程

[返回文档地图](../MAP.md)

## 最短工作流程

1. 阅读[文档地图](../MAP.md)、[执行计划](../计划/执行计划.md)与当前任务对应文档，按[项目提交技能](../../.agents/skills/project-commit/SKILL.md#主分支同步)获取并安全同步远程 `main`，检查已有代码和差异，确定本次独立改动的目标；重复操作按[技能地图](技能地图.md)选择已有技能。
2. 按[全局约束](../../AGENTS.md)实现当前需求；存在未确认的产品行为或交付要求时，先明确需求，不把猜测写成既定事实。
3. 按全局约束第 4 条选择必要验证并复用已有结果；文档与技能完成内容更新后直接进入提交。
4. 下表所列事实变化时使用[文档同步技能](../../.agents/skills/project-doc-sync/SKILL.md)维护对应文档，再用[项目提交技能](../../.agents/skills/project-commit/SKILL.md)自动提交、推送本地 `main` 并确认与 `origin/main` 一致。实现符合现有文档时无需改文档；同步失败时如实报告。

## 按改动维护

| 发生的变化 | 必须更新的权威文档 |
| --- | --- |
| 产品目标、行为、平台、范围或验收标准改变 | [产品规格](../产品/产品规格.md) |
| 技术选型、代码入口、模块职责或依赖改变 | [架构地图](../架构/架构地图.md) |
| 任务状态、下一步、阻塞或遗留问题改变 | [执行计划](../计划/执行计划.md) |
| 安装、运行、构建、交付或验证方式改变 | [架构地图的实际命令](../架构/架构地图.md#实际命令)及相关流程 |
| 新增、移动或删除文档 | [文档地图](../MAP.md)或所属主题页，以及所有受影响引用 |
| 全局约束改变 | [AGENTS.md](../../AGENTS.md) |
| Claude Code 的职责边界或 Codex 调度方式改变 | [CLAUDE.md](../../CLAUDE.md) |
| 项目技能新增或调整 | [技能地图](技能地图.md)、对应 SKILL.md 及必要的工具入口 |

用户最新要求与既有文档冲突时，以用户要求为准并同步修正文档。规格与代码不一致时，明确区分预期行为、当前实现与缺口；不得通过修改完成状态掩盖未实现功能或未执行验证。

技术选型、代码入口、模块职责或依赖落地后，只在[架构地图](../架构/架构地图.md)记录真实存在的路径与边界，不预建尚未实现的模块。运行相关文档只记录实际可用命令，不提供推测性命令。

## 验证与交付

- 验证范围与禁止事项以[全局约束](../../AGENTS.md)第 4 条为准。
- 最终交付使用实际交付方式运行产物，完成产品规格约定的核心流程，并确认必要资源可用。
- 未执行或未通过的检查如实写入提交正文；需要后续处理的问题记录到[执行计划](../计划/执行计划.md)，不宣称验证已通过。
