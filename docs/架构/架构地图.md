## 当前实现

`index.html` 的 `#game-viewport` 统一承载加载页、三维场景和界面；`src/loading.css` 在首屏即建立居中的横向 16:9 容器，页面其余区域为黑色。界面尺寸与断点读取该容器，长页在 `#app` 内滚动；`engine.ts` 通过 `ResizeObserver` 读取场景实际宽高，同步渲染器、后期和相机比例。

当前唯一开发与交付主线为根目录的 Three.js 0.187 + Rapier 0.21 + TypeScript 7 + Vite 8 网页工程。场景、物理、界面与交付均围绕现有浏览器工程组织。

网页依赖、物理 WebAssembly、道路数据和美术资源从本地加载，使用固定 60 Hz 物理步长和 Three.js Timer。显示按剩余物理时间在前后姿态间插值，镜头读取插值后的车辆姿态；基础跟车的水平位置统一跟随，朝向和垂直位移平滑，阴影中心按纹素对齐。完整四环整理为 590 条道路路径，双向主路闭环约 65.294／65.173 公里，辅路和连接匝道保留真实水平线形；单局目标为 20000 米，以约 10 分钟为节奏目标。

`world.ts` 加载真实道路、既有模型材质、HDR 与中文字体，建立原道路和建筑场景。路面采用米制 UV 和共享端点的连续道路带，开启 Rapier 内部边修正以减轻接缝颠簸，重叠路面与标线设置深度偏移；道路外缘生成带开口的护栏，只按 OSM 共同节点与同层道路连接留口。桥隧高度依据层级与连续缓坡推定，并非测绘实景。外部路网末端封闭，地面装饰不能当作可驾驶区域。

`cyber-scene.ts` 在既有道路碰撞和空域代理初始化后接入赛博朋克雨夜渲染：原几何、实例矩阵、碰撞和车型不变，场景材质改为湿润路面与冷色夜窗；叠加沿路程序化楼体、中文霓虹、雨雾、局部水平积水和低强度电影后期。新楼体避让真实道路及原建筑占地，仅作视觉层，不加入物理或空域代理。天气跟随显示用车辆姿态，使用比赛时间，暂停冻结；新增渲染只作用于游戏 WebGL 画面，不改变 UI。原场景静态对象按完整包围球在约580米夜雾后剔除，近处恢复原可见性，LOD控制父组；该剔除不改相机视锥、NPC可见性或碰撞，夜景阴影使用1024贴图。

渲染按空间块合并网格与实例，树木按约 80 米块切换远近几何，其他实例和表面按约 500 米组织；最近道路查询使用空间索引；护栏碰撞按玩家与所有动态警车所在区域共同激活，接触中的块保留。警方导航基于真实共享节点的方向道路，近距离仍保留道路走廊约束；前视跟踪、多车分工与实体撞击独立于比赛引擎，直升机使用单独的动态跟踪与遮挡查询。普通交通使用独立的有向车道网络与轻量驾驶规划，按真实连接续接与分流，感知同层前车、玩家和警车；正常行驶采用 Rapier 运动学车体，接触玩家、警车或已动态化 NPC 前按车型质量切换为动态并继承速度，受撞后自由撞偏、飞起或翻滚，实际姿态继续供避让与远距安全回收使用。车体与护栏使用圆角碰撞形状，低摩擦护栏允许轻擦滑行，正撞实体仍阻挡；强车辆碰撞另按约化质量施加受限向上点冲量，同一车对持续接触只触发一次。SUV、摩托与骑手、两类住宅、办公楼与两类行道树已接入 Tripo 生成 GLB；普通交通混合使用 SUV、摩托、配送货车、大货车与公交，警车复用 SUV。直升机仍是程序化外观；生成 SUV／摩托已接入局部视觉车损，真实软体材料破坏未实现。

`public/assets/art/` 中的 Poly Haven CC0 沥青、混凝土、HDR 和中文字体已由网页加载。两张 V2FUN 美术参考保存在 `docs/调研/参考图/`，用于方向比较，没有把参考图片当作游戏内模型。

生成 SUV／摩托的轻量车损保留连续外壳：玻璃保持不透明表面并叠加局部裂纹，保险杠保留形状并参与受限凹陷，仅后视镜、护手可脱落并封闭挂点。源几何共享不可变的分件、接缝权重、空间分桶与邻接缓存；每车独立可变几何、伤区和材质参数，最后一个使用者释放分件 GPU 资源，重开复用缓存拓扑。接缝固定，汽车／摩托累计位移分别限于 12／5.5 厘米；撞击按区域合并，每约 0.09 秒批处理并只更新局部顶点与法线。车轮、骑手保持原资源，主车体碰撞形状不随视觉凹陷重建；来源及完整许可见资产来源文档。

## 网页资源缓存

`vite.config.mjs` 调用 `scripts/resource-cache.mjs`，生产构建时为公开资源计算 SHA-256 内容摘要，注入版本表，并统一给 HTML 预加载、CSS 背景和 `src/asset-url.ts` 返回的运行时地址添加独立 `?v=内容摘要`。摘要不使用游戏版本号或构建时间，未改变的文件在后续构建中保持相同地址。程序与样式继续使用 Vite 自带的内容哈希文件名。

`src/resource-cache.ts` 在生产环境动态载入主程序前注册当前基础路径下的 `sw.js`，首访等待接管；`src/bootstrap.ts` 保留加载失败入口。Worker 源码位于 `scripts/resource-worker.js`，构建时写入产物。导航请求使用网络重新验证；同源、当前子路径内带内容版本的成功完整资源按需写入 Cache Storage，再次访问直接命中，不预取整包。模型等公共资源与程序文件分别缓存，前者每条路径保留最近两版、总计最多 128 条，后者最多 8 条，避免程序发布挤占大资源缓存。缓存名按站点基础路径隔离，不删除其他应用缓存或成绩。

音乐地址同样带独立内容摘要，但音视频和 Range 请求交由浏览器 HTTP 缓存与原流式加载处理，不将 206 分片当作完整资源。HTML、Worker 脚本和无版本资源不进入永久缓存；注册或存储失败会记录中文警告，继续正常网络加载。开发服务不注册 Worker；生产缓存需要 HTTPS 或 localhost／127.0.0.1，支持 GitHub Pages 的 `/human-overdrive/` 子路径。此缓存用于减少重复下载，不提供离线启动保证，资源解析、物理和场景构建仍会执行。

## 实际命令

### Three.js 主线

在仓库根目录使用 Node.js 与 npm：

| 目的 | 命令 | 结果 |
| --- | --- | --- |
| 安装依赖 | `npm install` | 安装 `package.json` 与锁文件声明的本地依赖 |
| 启动开发 | `npm run dev -- --port 5173` | 本机 `http://127.0.0.1:5173`；不指定端口时 Vite 默认 5173 |
| 编译与打包 | `npm run build` | 先执行 TypeScript 编译检查，再用 Vite 生成 `dist/` |
| 预览产物 | `npm run preview` | 本机 `http://127.0.0.1:4173`，需先生成 `dist/` |
| 更新道路 | `node scripts/fetch-road-data.mjs` | 联网查询 Overpass 并更新本地道路数据，常规启动无需执行 |

游戏通过本地 HTTP 服务运行，不以双击 HTML 的方式启动。生产交付为静态 `dist/`，依赖与资产随包提供；本机成绩按浏览器与站点地址隔离，开发地址和预览地址不会共享排行榜。

### GitHub Pages 自动发布

[在线游戏](https://kinoward.github.io/human-overdrive/)由 `.github/workflows/deploy-pages.yml` 发布。仓库 Pages 的发布来源使用 GitHub Actions；每次向 `main` 推送都会构建并发布，也可在 [Actions 页面](https://github.com/kinoward/human-overdrive/actions/workflows/deploy-pages.yml)手动运行，其他分支不发布。

构建任务使用 Node.js 24、npm 缓存与 `npm ci`，随后执行 `npm run build -- --base "$PAGES_BASE_PATH/"`。`PAGES_BASE_PATH` 来自 `actions/configure-pages`，当前为 `/human-overdrive`。TypeScript 或打包失败时不会部署；成功后只上传 `dist/`，由独立部署任务以 `pages: write` 和 `id-token: write` 权限发布到 `github-pages` 环境。并发发布串行执行，不中断进行中的部署，无需额外配置个人访问令牌。

运行时道路、模型、字体和界面图片使用 `import.meta.env.BASE_URL`；HTML 与 CSS 资源由 Vite 随构建基础路径改写。本地开发和普通构建仍默认使用根路径；如需本地预览 Pages 产物，执行 `npm run build -- --base /human-overdrive/`，再执行 `npm run preview -- --base /human-overdrive/` 并打开 `http://127.0.0.1:4173/human-overdrive/`。

当前工程此前已通过 `npm run build` 并在 Chrome 启动，范围见[执行计划](../计划/执行计划.md)。主包包含物理 WebAssembly，大小随场景与资产接入变化；美术资源、源道路数据和字体另随公开目录分发。已在最终预览入口人工驾驶，本轮前台短程起步窗口约 33–60 FPS，存在场景负载波动，画面插值、汽车与摩托接地已人工体验；该样本不代表最高追捕或全线路段的表现，首次加载和内存尚未定量测量。

## 复用与数据边界

用户提供的 [Three.js 创建场景教程](https://threejs.org/manual/pages/creating-a-scene.html)、[API 文档](https://threejs.org/docs/)和 [GitHub 源码](https://github.com/mrdoob/three.js)是官方技术资料入口，不是已安装的项目技能。车辆实现参考官方 Rapier 车辆示例的射线悬挂思路，Timer 与 WebGL 2 使用官方 API；游戏流程、城市路网、追捕与评分由本项目组织。

完整四环数据通过 Overpass 离线查询并筛选主路闭环、辅路与相连匝道。抓取脚本支持 `--input <原始 OSM JSON>`，可使用 Chrome 中 Overpass Turbo 导出的数据复现；导入时要求双向主路形成完整闭环。源数据与派生数据按 ODbL 分发，来源和实景简化说明见[资产来源](../../ASSET_LICENSES.md)。

模型整理使用独立工具目录，不增加游戏运行依赖。已有 GLB 随仓库提供，常规启动不执行生成或整理。需要从平台原始导出复现时，先在独立目录安装 `@gltf-transform/core@4.5.1`、`@gltf-transform/extensions@4.5.1`、`@gltf-transform/functions@4.5.1`、`meshoptimizer` 与 `sharp`，再执行 `node scripts/prepare-generated-models.mjs <原始GLB目录> <工具目录>`。脚本中的轮轴映射与尺度对应本批固定平台资产，换源模型时需重新核对。

补充街景模型使用同一工具目录，执行 `node scripts/prepare-streetscape-models.mjs <本批原始GLB目录> <工具目录>`，只处理 `brick-apartment.glb`、`office-block.glb` 和 `slender-tree.glb`。最终尺寸保留生成比例，以包围盒约束摆放；运行时对新树过亮叶色作局部校正，保留树干和其他模型材质。

路侧补充批次执行 `node scripts/prepare-roadside-models.mjs <本批原始GLB目录> <工具目录>`，只处理 `lush-shrub.glb` 和 `bus-shelter.glb`。灌木近景2908面、远景440面，保留三张1K材质贴图；候车亭约5995面、三张2K材质贴图。低矮绿化和立面小件不投影，主要树木与楼体保留投影。

玩法规则统一维护在[产品规格](../产品/产品规格.md)。

街机驾驶方案与候选物理体系见[车辆控制调研](../调研/车辆控制体系.md)。共享驾驶核心每个固定步计算纵向、横向和偏航修正，按动态车体质量与世界空间惯量转换成冲量，不直接覆盖位置、旋转或完整速度。射线车辆只保留悬挂、接地和车轮滚动读回，逐轮发动机、制动及侧向摩擦不再重复提供驱动。汽车至少两轮接地、摩托至少一轮接地且未明显倾倒时才提供主动驾驶修正；碰撞恢复降低抓地与转向权重。

车身显示在物理姿态下增加以轮胎接地线为支点的视觉层，摩托压弯与汽车小幅姿态按固定步更新并插值，不改变刚体翻倒或里程依据。正转向统一表示右转，警方路径跟踪使用相同符号。共享镜头在基础跟车计算后读取车辆速度与输入，不参与物理和里程；视野最高限制为 82°，暂停清理动态效果，开局显式重置历史状态。
