# NPC 交通行为调研

[返回文档地图](../MAP.md)

调研日期：2026-10-31。

本文记录普通 NPC 车辆行进和避让的本轮设计依据。它不替代[产品规格](../产品/产品规格.md)中的已确认玩法，也不将待落地的设计写成已验证行为；实际参数与实现以最终代码为准。

## 现状问题与目标

现有道路由有向中心线路径、实际同层连接和实体边界组成。普通交通若只沿路径匀速前进，容易在慢车、匝道汇入和玩家接近时形成追尾、穿模或不自然的急转；若按空间任意转向避障，又会越过主辅路隔离带或偏离道路。

本轮目标是在最多 42 辆普通车辆下，令车流能沿可行驶道路持续前进、跟随慢车、在安全条件下变道或汇入，并在近距离风险上主动制动。方案优先服从真实道路连接和隔离边界，不追求完整现实交通法规仿真。

## 本轮设计与取舍

每辆普通 NPC 正常行驶时使用参数化的有向车道状态：所属道路、沿线进度、行进方向和车道横向偏移。规划只允许在当前道路、经道路网络确认可达的后继道路，或相邻可用车道中移动；变道过程平滑插值，不能跨越隔离带或进入无连接的平行道路。受撞切换为动态车体后退出驾驶规划，由物理世界继续决定实际位置与姿态。

纵向行进采用 IDM 跟车思想：按本车速度、同车道最近前车的净间距和闭合速度计算加速度。横向决策采用 MOBIL 启发式：先判断目标车道后车能否安全制动，再比较本车收益和对目标后车的影响。车辆在已选合法后继的汇入口检查前后空隙，无法安全汇入时先制动等待。

车辆在同层近距离范围额外使用 TTC 作为紧急制动兜底。TTC 只处理保持当前轨迹时的短时碰撞风险，不能代替车道约束、IDM 跟车或安全变道判断。

普通交通与警车职责分离：普通交通遵循跟车、礼让、汇入和安全回收；警车继续使用追捕导航和近距离撞击玩法，不受普通车辆的礼让策略约束。这样避免普通交通为追捕让路导致失去障碍压力，也避免警方被普通交通的变道冷却限制。

## 模型依据

### IDM 跟车

Treiber 的 IDM 将车辆加速度建模为本车速度、前车净间距与相对速度的函数；无前车时可把间距视作极大值。其常用形式为：

\[
\dot v = a\left[1-\left(\frac{v}{v_0}\right)^4-\left(\frac{s^*}{s}\right)^2\right],
\qquad
s^*=s_0+vT+\frac{v\Delta v}{2\sqrt{ab}}
\]

其中，\(v_0\) 为自由流目标速度，\(s\) 为净间距，\(\Delta v\) 为接近前车时为正的闭合速度，\(s_0\) 为静止最小间距，\(T\) 为期望时距，\(a\) 与 \(b\) 分别表示常规加速和舒适制动强度。模型将间距缩小、车速升高和闭合速度增加均转化为更强制动。

原作者的交互说明列出上述输入、参数含义和数值积分方式；其 IDM/MOBIL 论文的高速路示例使用 \(T=1.2\) 秒、\(a=1.5\) m/s²、\(b=2\) m/s²、\(s_0=2\) m，并强调为各车引入目标速度差异可避免同质车流过快进入静态状态。

来源：[Treiber，IDM 交互说明](https://mtreiber.de/MicroApplet/IDM.html)；[Kesting、Treiber、Helbing，MOBIL 原论文，第 8–9 页](https://mtreiber.de/publications/MOBIL_TRB.pdf)。

### MOBIL 安全变道

MOBIL 以底层跟车模型计算的加速度同时评估变道安全和收益。目标车道后车在变道后的预测加速度必须满足：

\[
\tilde a_n \ge -b_{\mathrm{safe}}
\]

在安全后，普通的对称变道收益条件为：

\[
\tilde a_c-a_c+p\left[(\tilde a_n-a_n)+(\tilde a_o-a_o)\right] > \Delta a_{\mathrm{th}}
\]

其中 \(c\) 是准备变道的车辆，\(n\) 是目标车道后车，\(o\) 是原车道后车；带波浪号的量表示变道后的预测加速度。\(p\) 是礼让系数，\(\Delta a_{\mathrm{th}}\) 防止为微小优势频繁变道。原论文示例给出 \(p\in[0,1]\)、\(\Delta a_{\mathrm{th}}=0.1\) m/s²、\(b_{\mathrm{safe}}=4\) m/s²；在匝道汇入示例中，临近合流端的车辆因前方虚拟障碍而获得更强的变道动力。

来源：[Kesting、Treiber、Helbing，MOBIL 原论文，第 5–10 页](https://mtreiber.de/publications/MOBIL_TRB.pdf)。

### TTC 紧急风险

当两个车辆保持当前轨迹且本车正在接近前车时，使用：

\[
\mathrm{TTC}=\frac{\text{净间距}}{\text{闭合速度}}
\]

美国国家公路交通安全管理局将 TTC 定义为在速度差保持恒定时的碰撞剩余时间，同时指出它不含两车加减速度，不能单独描述全部风险。因此本轮只将它用于覆盖常规加速和触发紧急降速；正在变道的车辆同时感知当前横向位置和目标车道。

来源：[NHTSA，前向冲突指标报告，第 5-24 至 5-25 页](https://www.nhtsa.gov/sites/nhtsa.gov/files/809900all.pdf)。

## 游戏化参数和边界

本轮普通交通按道路类别设置目标速度：主路约 65–90 km/h，辅路约 30–45 km/h，匝道更低；同类车辆再加入有限差异。IDM 和 MOBIL 的论文参数是模型示例，不能直接当作本项目最终数值。

普通车辆采用适中的礼让系数和数秒变道冷却，避免连续横跳；只有目标车道前后净距、预测制动和可达道路连接均满足时才开始横移。匝道汇入必须在可行车道中寻找安全空隙；无法安全汇入时先减速。通往关卡外部的死端不作为继续行驶路径，车辆应在抵达前减速停车，或在距离玩家足够远、不会造成突变观感和碰撞风险时安全回收。

NPC 采用运动学规划与动态受撞混合机制：正常车流保留 Rapier 运动学车体，在接触玩家、警车或已动态化 NPC 前，按车型配置质量切换为动态并继承运动速度，之后可被撞偏、撞飞或翻滚，不由 AI 拉回道路；其他车辆继续感知其实际位置与速度，远离观察范围后才安全回收并恢复规划。车型质量见[产品规格](../产品/产品规格.md)。该取舍控制最多 42 辆局部车流的计算量，不能保证避免玩家突然插入、瞬时横切或高速倒车造成的所有碰撞。窄双向单车道匝道已加入入口预约与方向轮换，防止普通 NPC 主动形成对向占用；不提供玩家蓄意堵路或已发生异常重叠时的通用倒车解堵。首版不包含红绿灯、交叉口路权、完整让行法规、真实驾驶员反应时延或全局最优交通流仿真。

## 补充调研：连续占用、汇入与窄路

SUMO 的连续变道把动作划分为开始、前保险杠中心跨越车道线与完成三个事件；子车道模型中，变道车辆在横移期间会同时关联当前车道、目标车道和影子占用，并按所占横向区域进行跟车与安全间隙判断。对应本项目，开始变道后的车辆应持续参与源、目标两侧的前后车和 TTC 查询；发生新冲突时先冻结横移并制动，只有回退扫掠范围安全时才返回原车道，不能在冲突中直接跳到目标车道。来源：[SUMO 连续变道输出](https://sumo.dlr.de/docs/Simulation/Output/Lanechange.html)、[SUMO 子车道模型](https://sumo.dlr.de/docs/Simulation/SublaneModel.html)。

SUMO 将速度收益、路径战略、合作与默认车道等列为不同的变道动机；其安全输出还分别记录目标车道前后车的实际与安全间隙。本项目只保留速度收益、合法道路续接和匝道合流，并在变道期间预留两侧车道，避免加入完整路权和驾驶员个性系统。来源：[SUMO LC2013 参数](https://sumo.dlr.de/docs/Definition_of_Vehicles%2C_Vehicle_Types%2C_and_Routes.html)、[SUMO 安全输出](https://sumo.dlr.de/docs/Simulation/Safety.html)。

SUMO 指出加速车道车辆接近末端时会因无法确定变道成功而减速；车道缩减可设为 zipper，短距离上下匝道交织在高密度时可能死锁。对应本项目，合流区应随剩余长度提高安全变道意图，并在连续安全候选之间按到达或等待顺序轮换；主线车仅在自身跟车与 TTC 余量允许时让出空隙，合流车到让行点仍无安全空隙则停车等待。该轮换是游戏化取舍，不复刻 SUMO 的网络路口模型。来源：[SUMO 高速路与匝道](https://sumo.dlr.de/docs/Simulation/Motorways.html)、[SUMO zipper 路口](https://sumo.dlr.de/docs/Simulation/Intersections.html)。

SUMO 的反向行驶机制会检查来车、完成超越所需时长、队列末端空位和有限前视距离，并明确列出视线遮挡和道路几何等限制。对应窄双向单车道，本项目应在入段前设置共享区预约和让行点：已有反向预约或对向车已进入时不再放行；同向车可成批通过，方向则按等待顺序轮换。本轮实现以入口预约和禁止反向生成阻止普通 NPC 形成双向占用；已经异常进入共享区的对向车辆需要另行设计恢复策略，不承诺能靠制动自动解开。远距安全回收不能当作常规通行规则。来源：[SUMO Opposite Direction Driving](https://sumo.dlr.de/docs/Simulation/OppositeDirectionDriving.html)。

SUMO 的弹道积分以固定加速度计算本步位置和速度，IDM 实现允许负的下一速度表示车辆会在本步内停下。项目的路径进度不能直接采用这种负速度，否则会出现倒退；当 \(a<0\) 且停车时刻早于步长时，应仅累计 \(v^2/(2|a|)\) 的制动距离并将速度归零。来源：[SUMO 仿真规范](https://sumo.dlr.de/docs/Specification/)、[SUMO IDM 实现](https://sumo.dlr.de/doxygen/d7/dae/_m_s_c_f_model___i_d_m_8cpp_source.html)。

Rapier 官方说明，位置控制的运动学刚体不会被物理接触改变轨迹；若要避免它穿过障碍，必须由调用方使用场景查询或其他控制逻辑。本轮已接入 `traffic-motion.ts`：用 `World.castShape` 扫掠计划平移，对玩家、警车和其他 NPC 用相对速度 `castCollider` 检查运动交会，并检查提交旋转后的目标形状交叠；查询过滤道路与自身。安全提交规则拒绝新增或加深接触，已经接触的动态车辆仅在实际目标形状减轻接触时允许分离，避免把脱离动作永久钳住；拒绝时交通规划回滚本步路径、横移和车轮行程并制动。`traffic-physics.ts` 在实际求解前预测动态车辆接触，将受影响 NPC 释放为有质量、继承速度的动态车体，并继续检查后续连锁接触。正常行驶的道路预测、跟车、车道预约和合流决策继续生效；规划检查仍是固定姿态平移扫掠与目标旋转检查的组合，未完整覆盖旋转过程的连续碰撞检测。来源：[Rapier 运动学刚体](https://rapier.rs/docs/user_guides/javascript/rigid_body_type/)、[Rapier JavaScript `castShape`](https://www.rapier.rs/javascript3d/classes/World.html)。

## 参与感与异质车流

此前的候选出生点只按玩家周围约 125–560 米的空间距离抽取，回收也要到约 680 米外才发生；它没有要求车辆与玩家同向、位于玩家前方或可沿当前道路继续抵达。玩家高速超越后，落在身后的车辆仍会占用总数，前方车流配额会逐步耗尽。这是普通车流参与感偏弱的设计缺口，不代表 IDM、MOBIL 或道路连接本身失效。

建议将车流组织成玩家周围的局部可读性泡泡：前方参与层优先放在玩家当前合法行进方向的连续道路走廊内，周边背景层用于侧方和远景，远距层才承担储备。前方层设置优先配额，车辆超越后进入安全后方距离即可候选回收，优先补到前方较远且合法的连续路段；候选仍须通过前后空隙、短时 TTC、同层道路连接和当前镜头可见性检查，不能在玩家眼前突现。此为保证追逐与穿行节奏的游戏化调度，而非全图真实交通密度复原。

SUMO 将道路容量与车辆长度、最小间隙、时距、速度分布和变道行为共同关联，且车辆插入会检查上下游及相邻道路段的安全条件。这支持按前向道路走廊维持局部密度、以车型实际长度参与净距判断的取舍，但不应把其每小时流量公式直接换算为本项目的局部车流预算。来源：[SUMO 道路容量](https://sumo.dlr.de/docs/Simulation/RoadCapacity.html)、[SUMO 车辆插入与连接检查](https://sumo.dlr.de/docs/Specification/)。

SUMO 的 `vType` 以长度、最小间隙、加减速、时距、最高速度和个体速度因子表达不同车辆，并支持按类型分布和速度分布生成异质车流。项目可据此将驾驶配置独立于渲染模型：同一普通交通逻辑读取各类型的几何、速度、跟车时距、加速和道路许可，而不为每种模型复制一套交通算法。来源：[SUMO 车辆类型与类型分布](https://sumo.dlr.de/docs/Definition_of_Vehicles%2C_Vehicle_Types%2C_and_Routes.html)、[SUMO 速度与流量随机性](https://sumo.dlr.de/docs/Simulation/Randomness.html)。

| 类型 | 在局部车流中的职责 | 约束 |
| --- | --- | --- |
| SUV／普通轿车 | 构成主要可追越车队与稳定间隙 | 可使用已确认的普通车道和连接 |
| 摩托 | 提供小体量、节奏较快的可见目标 | 不在未实现的子车道逻辑中穿缝 |
| 配送车 | 提供中等速度和体量差异 | 减少激进变道，服从道路续接 |
| 大货车 | 少量、清晰的移动障碍与超车决策 | 优先宽路右侧车道，过滤窄双向路、过短或急弯匝道、急转分支及无可持续后继的道路 |
| 公交 | 作为低频大体量背景目标 | 仅在路线连续、宽度和转弯余量满足时加入 |

当前车型比例和性能已写入 `src/game/traffic-vehicles.ts` 的 `TrafficVehicleSpec`，属于街机游戏参数，不对应现实品牌规格或真实道路限行法规。SUV 和摩托复用已有官方生成模型，配送货车、大货车和公交为本轮通过主办方 Tripo 新生成并接入的 GLB；来源见 `public/assets/generated/traffic/SOURCES.json`。

## 当前落地

`traffic-network.ts` 预先按真实共享节点拆分有向道路，识别合流来源、近直角出口和窄路可离开方向，沿玩家实际道路与行进方向构造前后连续路段候选，再以空间索引补充周边候选；`traffic-right-of-way.ts` 管理窄路方向预约与入口限行；`traffic.ts` 按统一快照依次做候选决策、变道预约、运动计算，统一推进仍在正常驾驶的车辆。`traffic-vehicles.ts` 定义五类车型配置，`traffic-models.ts` 负责模型缓存与独立渐显材质；`traffic-motion.ts` 在提交到 Rapier 前检查平移、相对运动与目标旋转，拒绝危险移动并回滚规划；`traffic-physics.ts` 在动态车辆接触前切换受影响 NPC 的刚体类型并继承速度。`engine.ts` 根据实际车长、宽、高和质量创建圆角碰撞体，动态化后读取实际刚体姿态并保留为避让障碍，安全回收时恢复运动学规划；近失判定使用车型宽度，保留独立警方策略。

| 预测与积分 | NPC 沿道路与变道轨迹预测，玩家和警车按短时速度预测，并检查采样间的相对扫掠；本步提前停车时只累计到停车时刻，速度和实际前进量保持一致 |
| 物理提交 | Rapier 车体平移扫掠、动态相对扫掠与目标旋转交叠检查；拒绝新增或加深接触，已有动态接触允许实际减轻的分离；拒绝时回滚路径、横移和车轮行程 |
| 碰撞响应 | 玩家、警车或已动态化 NPC 的接触预测触发按车型质量释放，继承运动速度后由物理求解撞偏、飞起与翻滚；强车辆碰撞的受限向上点冲量按约化质量计算，持续接触按车对只触发一次，不对路面或护栏触发 |
| 出生与回收 | 主路初始前向候选约 55–460 米、辅路约 42–210 米，运行补车约 220–420 米；正常和受撞动态车辆均须超过安全后方距离或离开侧向观察区后才可回收，每 0.18 秒最多一辆，C 后视切换保留约 1 秒保护；回收时清除动态速度并恢复运动学类型 |
| 可见性 | 保留当前观察锥内近中距离车辆，补车优先视锥外或有现车遮挡的候选；365 米外允许远端渐显，回收后约 1.5 秒恢复可见。该近似不等于真实渲染遮挡查询，远端仍可能看见模型逐渐出现 |

当前变道收益只计算本车改善和目标后车代价，没有计算完整 MOBIL 中原车道后车的全部收益；这是一项游戏化简化，不能称为完整 MOBIL 实现。不同道路之间使用短连接曲线完成横向衔接，所有分支仍必须来自真实同层节点。普通 NPC 的原路跟随车不作为前车正常续接时的汇入障碍；玩家、警车及目标道路来车始终保留安全感知。窄路方向预约按整条道路持有，跨内部切段不释放，越过出口后再累计半车长加 3 米才释放，避免车尾仍在共享区时放入对向车辆。空路预约若出口变堵，会释放尚未进入的预约并重新选择可通行方向。

完整交通仿真、全路网密度校准和逐段人工驾驶验证均尚未完成；当前已支持受撞时动态化的 NPC，完整旋转连续碰撞检测与通用倒车解堵仍未纳入当前实现。本轮设计只为当前真实道路、匝道与追捕玩法提供可持续迭代的普通车流基础。

实际起跑数量、人工驾驶与性能验收范围统一记录在[执行计划](../计划/执行计划.md)。新增三款模型的轮轴与生成边界见[赞助资源与资产制作](赞助资源与资产制作.md)。
