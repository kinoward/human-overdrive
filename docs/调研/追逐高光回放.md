# 追逐高光回放

[返回文档地图](../MAP.md)

调研日期：2026 年 10 月 31 日。用户希望在比赛结束动画之后回看本局追逐高光。已基于本次调研实施第一版状态回放；前面的比较与估算保留技术取舍依据，实际行为和参数以「已实施的技术规格」为准，人工验证范围见执行计划。现有结束演出与成绩行为见[产品规格](../产品/产品规格.md)，开发状态见[执行计划](../计划/执行计划.md)。

## 结论与推荐体验

可沿用现有 Three.js + Rapier 网页工程实现，不需要更换引擎或新增后端。推荐比赛中保存动态实体的历史状态与真实事件，赛后用独立显示对象和电影镜头重放；回放期间不重新求解碰撞，也不修改正式成绩。自动筛选先采用现有玩法事件与明确规则，无需引入大模型。

实际流程为「成功／失败结束演出 → 本局高光回看 → 成绩页」，从整局精选最多 3 段；片段按真实记录长度裁切，不强行凑满总时长。近失、闪避可用侧前方跟拍，撞击或翻滚可用侧面和高位机位，关键瞬间短暂慢放；每段清楚标注「精彩回放」与事件名称，支持跳过全部、暂停和继续。没有其他候选时保留最后一段真实驾驶；没有可用历史记录时直接进入成绩页。

已实现基础记录、独立姿态播放、按版本保存的损伤外观和容量内碎片，完成核心流程人工预览；最高警力、长程内存及所有机位仍需继续实驾，不能将局部结果视为稳定帧率承诺。

## 官方能力与方案比较

| 方案 | 已核实的能力 | 对本项目的判断 |
| --- | --- | --- |
| 记录实体姿态并重新渲染 | Three.js 提供 [Vector3.lerpVectors](https://threejs.org/docs/pages/Vector3.html#lerpVectors) 与 [Quaternion.slerpQuaternions](https://threejs.org/docs/pages/Quaternion.html#slerpQuaternions)，可插值位置和旋转 | 推荐。保留实际轨迹与翻滚，支持新机位、慢放和分段跳转；需要另外记录外观和生命周期 |
| 记录输入后重新运行物理与 AI | Rapier JS/WASM 在同版本、相同初始化、增删顺序和步数等条件下提供[确定性](https://rapier.rs/docs/user_guides/javascript/determinism/)；官方同时指出 JavaScript 的部分数学运算可能影响跨平台初始化一致性 | 原理可行，首版成本高。还要完整复现游戏自身的导航、交通回收、可见性决策和时钟；物理确定性不等于整款游戏已可确定重放 |
| 定期保存整个物理世界 | Rapier 的[序列化](https://rapier.rs/docs/user_guides/javascript/serialization/)支持将 World 保存为 Uint8Array，并从快照恢复世界 | 可用于调试和回滚；不会自动保存独立的车损网格、UI、AI 私有状态和 Three.js 对象，不能直接当整局回放文件 |
| 持续录制游戏画面 | [Canvas.captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream)可捕获画布视频轨道，再交给 MediaRecorder 录制 | 适合保留原驾驶视角或后续导出视频；无法从已录画面得到原本没有渲染的其他机位，驾驶期间还要持续编码 |

上述推荐是结合项目的工程判断，不是官方给出的游戏回放方案。MediaRecorder 的格式应使用 [isTypeSupported](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static) 探测，返回支持仍不保证设备资源足够；画布捕获本身只有画面，DOM HUD 与音乐不自动包含在内，录制源还须保持可跨源安全读取。若以后需要更精细的视频导出，[WebCodecs](https://developer.chrome.com/docs/web-platform/best-practices/webcodecs)可处理逐帧编码，但仍要处理帧队列、资源释放和输出封装；本轮推荐先完成游戏内回看。

## 现有工程可以复用什么

- [engine.ts](../../src/game/engine.ts) 已有固定 60 Hz 比赛物理步、结束判定和独立开场／结尾状态。当前结束时先通过 onResultReady 保存成绩，结尾播完或跳过后才调用 onFinish 展示结果，正好可以在两者之间接入回放。
- [render-pose.ts](../../src/game/render-pose.ts) 已有前后两帧的位置与四元数插值；它没有长期历史缓冲，不能直接倒退几十秒，但插值方式可复用。
- [race-cinematic.ts](../../src/game/race-cinematic.ts) 已有车型机位、镜头时间线与减少动态效果处理，可复用其运镜方式；回看过去的追逐仍需新的事件目标和遮挡处理。
- [driving-score.ts](../../src/game/driving-score.ts)、[collisions.ts](../../src/game/collisions.ts)、[police.ts](../../src/game/police.ts) 已有可用事件信号。当前 RaceResult 只保存汇总成绩，没有历史轨迹，之前存下的比赛成绩无法据此补回高光。

| 高光候选 | 当前信号与使用边界 |
| --- | --- |
| 干净近失超车 | nearMiss 返回 true 时，已满足完整超越与实际获分条件；当时持有目标交通 ID。可补充间隙和相对速度用于排序 |
| 躲开警方攻击 | PoliceEvent.evaded 有警车 ID；DrivingScore.update 的获奖结果还经过控制状态、里程与冷却门槛。需要同时保留事件身份与是否获分，不能把全部扑空都显示成得分技巧 |
| 警车翻覆／失能 | flipped／disabled 为一次性事件，但翻覆确认晚于开始翻滚，需保留事件前画面；事件本身不证明由玩家造成，默认标题用「警车翻覆」，不能无条件写成「撞翻警车」 |
| 强碰撞与失控 | 碰撞帧已有 newIncident、feedback、强度、相对速度变化和接触位置，可去掉持续轻擦与同一事故的重复片段 |
| 高压突围 | 现有满压力统计是累计值，不是独立事件；需记录实际压力区间，再挑选持续受追、成功闪避或脱离近身车辆的段落 |

建议事件排序先考虑已确认的技巧、明显翻滚或强碰撞，再考虑持续追逐压力。相邻事件合并为一段，同一事故不反复入选；最终失败瞬间可作为候选，不应挤占整局所有其他高光。自动识别规则只决定回看片段，不改现有评分。

## 推荐记录与播放方案

### 记录真实历史，及时保留精彩段落

1. 只在 running 的固定物理步完成后采样，记录比赛时间与实际场景渲染时间，排除暂停和开场稳定悬挂的准备步。
2. 保留约 20 秒的环形缓冲。发生候选事件时保存前约 3 秒，并继续补齐后约 5 秒；接近比赛终点的片段截止于真实结束时刻，不把赛后慢动作误记为比赛历史。
3. 持续保留有上限的精选候选，例如最多 6 段、每段最多 8 秒；新片段按重要度替换较弱片段，并合并重叠区间。这样开局的高光不会在十分钟后被环形缓冲覆盖掉。
4. 结束时选出最多 3 段，按事件时间顺序播放，按总播放时长裁切；慢放只集中在关键瞬间，避免三段都慢放导致等待过长。

建议首个原型以 60 Hz 记录参与交互的动态实体，与现有物理步对齐；必要时再根据实机测量降低背景车辆频率。30 Hz 可以作为较低内存方案，但高速接触与翻滚细节更稀疏：以 200 km/h 为例，两个样本间约行进 1.85 米，60 Hz 约为 0.93 米。插值改善显示连续性，不会恢复未被记录的碰撞细节，不能把低频采样当作任意倍慢放的高精度记录。

### 记录范围与字段

记录玩家及回放机位覆盖范围内的警车、残骸、普通交通和直升机，包括后方及原镜头遮挡中的实体；不能只采样当时相机看得到的对象，否则换机位会缺车。初版可以记录现有 42 个普通交通槽位，避免过早引入复杂的按视角取舍。

| 类型 | 必要内容 |
| --- | --- |
| 共用时间与身份 | 比赛时间、simulationTime + presentationTime、回放 ID、实体类型和车型／颜色、出生／消失时刻、重定位代次 |
| 车辆根姿态 | 世界位置、四元数、速度、显隐和透明度 |
| 玩家与警车 | 每轮悬挂、转向和累计滚动量，车身视觉压弯／俯仰，刹车灯与警灯状态 |
| 普通交通 | wheelDistance、转向灯、刹车灯、appearance；不跨重定位断点插值 |
| 直升机 | 根姿态、累计旋翼角、探照灯开关与目标世界位置 |
| 事件与外观 | 涉及实体、类型、重要度与接触位置，以及片段起点车损和后续实际外观变更 |

车轮和旋翼要保存连续累计角或距离，避免对每圈归零的旋转值插值而出现倒转。普通交通 ID 是可重定位的槽位，需要「槽位 + 代次」或明确的生命周期断点；警车销毁后不能依赖原模型引用。碰撞时的 Rapier handle 只用于当帧关联，再映射到回放身份。

历史车损也需要在比赛中保留有界的外观检查点和已提交变更，选段时保存起点之前的最近检查点及到起点的变化；不能在事件发生后才复制当前网格，冒充事件前的车况。检查点及其依赖变化须与精选片段共同保留，并在没有片段或缓冲引用时释放；频率和峰值内存另行测量。

### 独立视觉层播放

真实比赛世界停留在终局，回放使用共享不可变模型资源的独立显示对象，由历史样本直接驱动，不调用 drive、World.step、交通规划、追捕、计分或成绩保存。历史中已销毁的车辆按保存的车型元数据建立显示对象；当前原动态对象统一隐藏，避免出现两套车辆。

回放相机围绕记录的玩家和事件参与者取景；遮挡查询读取回放位置对应的静态道路与建筑代理，不能用终局动态刚体的位置判断历史机位是否受阻。场景分块、雾后剔除和灯光焦点也需跟随回放焦点。片段切换时使天气、积水、路灯平滑及空间缓存回到该段时刻，防止终局画面状态泄漏到较早片段。

在现有 outro 完成分支插入 replay 状态，保留 pendingResult；高光结束或跳过后沿用原 onFinish 打开成绩页。成绩仍只在原结束判定时保存一次。暂停恢复记住当前片段与播放时间，重开或离开时释放记录和回放对象。回放统一使用追逐段配乐，各片段跳转不重置音乐，结果页再切回对应结算段；减少动态效果时宜用固定跟拍并减少片段数量。

## 内存与性能预算

以下只估算姿态数据，不是测量结果。以固定大小 TypedArray 存储、64 个实体预算、每实体每样本 128 字节、20 秒环形缓冲与最多 6 段各 8 秒候选计算：

| 采样率 | 环形缓冲 | 精选候选最多 48 秒 | 合计 |
| --- | --- | --- | --- |
| 30 Hz | 约 4.7 MiB | 约 11.3 MiB | 约 16 MiB |
| 60 Hz | 约 9.4 MiB | 约 22.5 MiB | 约 32 MiB |

公式为「实体数 × 每样本字节数 × 采样率 × 保留时长」。64 个实体是设计假设，不是当前引擎的硬上限；10 辆完好警车之外可能还有残骸，碎片也另有数量。正式实现要确定实体容量及优先保留玩家和事件参与者的策略，并额外预算身份表、事件、车损、碎片和显示资源。若全程保留同规格 10 分钟的 60 Hz 数据，单姿态流就约 281 MiB，因此首版推荐有界缓存与即时保留精选片段。

记录时复用预分配缓冲，不逐帧生成 JSON 或复制整个场景；不要在驾驶时持续编码视频。现有高警力表现仍有低帧窗口，新增记录开销、车损快照峰值和片段切换耗时必须在后续原型实机体验中确认，不能只据上述数据大小推断帧率。

## 主要还原难点

| 难点 | 实施要求与可接受的分阶段边界 |
| --- | --- |
| 历史车损 | 当前 VehicleDamage 提供 impact／update／dispose 及汇总信息，但没有可复用的快照或恢复接口。仅显示最终车损会让后来的凹陷提前出现；需要片段起点外观快照，加实际已提交的变形批次和部件变化，不逐帧复制完整顶点 |
| 损伤重建 | 原始碰撞会被合并、限流并受部件／碎片预算影响，单纯重播 impact 输入不保证同样外观。若采用命令重建，应保存 update 实际提交的局部变化 |
| 碎片 | 碎片寿命短且已被回收，需要独立历史身份与姿态；重新跑碎片物理不能保证精确还原。基础版若省略，应明确为简化回看 |
| 车型生命周期 | 交通槽位重定位与警车真正销毁都需要历史元数据，不能只记当前数组下标或对象指针 |
| 倒拨场景时间 | 雨雾有绝对时间输入，路灯等还有历史平滑状态；需要片段起点复位，不能只更改一个 elapsed 值 |
| 新机位 | 回放从未见过的方向会暴露近处未记录实体或缺少场景代理，需按空间覆盖采样并限制机位范围 |

## 推荐落地顺序与完成标准

已完成事件记录、限定容量的历史缓冲和独立显示回放，覆盖轨迹、翻滚、车轮、灯光、损伤版本与容量内碎片；结尾到回看再到成绩页、暂停与跳过均已接通。

后续根据实驾继续调校主体机位、静态遮挡和高压力下的资源预算；有导出需求时再评估对选定片段重渲染并编码视频，而不是给每局持续录屏。

后续只按项目约定做必要编译、启动和核心流程人工验证：分别体验两种车型、成功／翻覆／围堵后回看、早期高光保留、重复事件合并、车辆回收断点、暂停／跳过／重开、成绩不重复写入，以及高警力时的内存与帧率变化。本轮已完成构建及核心流程人工预览，具体证据和未覆盖项目见执行计划。


## 已实施的技术规格

### 模块与状态边界

- `race-replay.ts` 管理回放时钟、片段主体、镜头与原画面恢复；`replay-buffer.ts` 管理记录帧、事件候选和引用生命周期；`replay-sources.ts` 定义各车型、直升机与碎片的采样通道；`replay-visuals.ts` 管理不可变外观、几何页共享与 GPU 显示实例。
- `engine.ts` 在每个 running 物理步完成后，把显示姿态临时同步到该步真实状态再采样；正常显示仍使用原有前后帧插值。开场、悬挂准备步、暂停、赛后慢动作和回放均不新增比赛样本。
- 原结束判定先保存成绩，outro 结束或跳过后进入 replay，高光完成或跳过后才调用原 onFinish。replay 不调用 World.step、驾驶、交通规划、追捕、计分或保存；暂停状态记住原阶段，重开／离开清理记录和显示资源。

### 帧结构与实体覆盖

- 正式采样为 60 Hz，环形容量 1201 帧，约 20 秒。每帧按 16 个实体对齐分配 Float32Array 和 Int32Array，并从小型帧池复用；共享帧通过引用计数同时服务环形窗口与候选片段，保留候选不复制整段数组。
- 每个实体占 48 个浮点槽，前 13 个为位置、四元数、速度、渐显、缩放和可见性，其余保存类型专属通道；另有 1 个整数回放 ID。车轮与旋翼保存累计旋转／距离，避免归零处倒转；轮胎、压弯、灯光和探照灯目标单独记录。
- 以玩家为中心记录 480 米内动态实体，玩家始终优先，其他车辆与直升机按距离排序，碎片随后；每帧最多 96 个实体。记录不依赖原镜头可见性。极端拥挤时超出容量的远实体不进入该帧，因此不承诺所有远端碎片均被保留。
- 普通交通在 relocated 时递增代次，身份使用模型 UUID 与代次组合；警车、直升机和碎片按独立模型身份记录。帧持有不可变显示外观，而不是依赖终局实体继续存活，回收和销毁不会把旧轨迹连到新车。

### 高光筛选与主体镜头

- 初始片段范围为事件前 3 秒、后 4 秒；相邻事件合并后最多延长到 8 秒，最多保留 6 个候选。新候选按重要度替换较弱片段，末尾按真实结束时刻截断。赛后按重要度去掉重叠片段，再按比赛先后播放最多 3 段。
- 近失和获分闪避接现有评分结果；强碰撞接 newIncident，持续轻擦不反复入选；持续受追的干净行驶每隔至少 12 秒产生较低优先级候选。终局保留最低优先级的真实驾驶回顾，避免普通结束覆盖整局技巧。
- 警车翻覆／退出追捕绑定其回放身份，镜头跟随事件警车；主体尚未进入记录或已丢失时不生成错误主体画面，选段起止按主体实际存在范围裁切。其他事件以玩家为主体。不会把未确认因果的翻覆宣称为玩家撞翻。
- 常态播放约 1.2 倍速，在事件前后约 0.65 秒局部使用 0.55 倍慢动作；机位随片段变化，保持世界竖直方向。减少动态效果只选 1 段、固定后方跟拍，以 1.25 倍速播放并关闭慢动作。

### 历史外观、灯光与场景

- `VehicleDamage.revision` 只在实际提交损伤批次后递增。显示外观在初次出现及版本变化时保存，包含当时的几何、部件可见性和材质，较早画面不会借用最终车损。
- 几何底本按原几何缓存，位置与法线以 192 个分量为一页；新版本只复制内容变化的页，其余页与前一版本共享。播放时按使用者引用取得独立 GPU 几何，旧实例退出或版本替换后释放，不把所有历史版本同时上传。
- 损伤裂纹依赖自定义着色回调及其参数，普通材质复制不足以表达历史变化；`cloneReplayMaterial` 为损伤材质建立独立参数副本，普通材质保留其自定义着色行为。纹理继续共享，回放退出只释放自己拥有的几何和材质，不销毁原纹理。相关基础能力见 [Three.js Material](https://threejs.org/docs/pages/Material.html#onBeforeCompile) 与 [Object3D](https://threejs.org/docs/pages/Object3D.html#clone)。
- 碎片按真实出生、姿态、缩放和消失状态记录；不在回放中重新模拟碎片。原动态模型和道路近光池在播放期间隐藏，回放显示独立车辆与附近 4 束照明；不复用终局灯光位置。
- 雨雾、涟漪与后期读取已记录的场景时间。切段时复位附近光照与空间缓存，场景分块、阴影和静态遮挡查询跟随历史主体，结束时恢复原镜头。

### 实际预算与验证边界

先前 16／32 MiB 表格是每实体 128 字节的方案估算。实际实现为每实体 192 字节通道数据加 4 字节 ID，并按实体容量对齐：64 个实体时，20 秒环形姿态数组约 14.4 MiB；96 个实体及全部 6 段候选各 8 秒的极限组合，含端点和少量空闲帧池，姿态数组约有 74 MiB 的上界，重叠帧共享时更低。以上均不包含外观页、模型、事件对象与渲染资源，不能称为整个功能的总内存上限。

33.47 秒、2008 样本的人工预览中，窗口保持 1201 帧，较早片段仍可回看；当时有效姿态数组约 15.4 MiB，筛成 3 段后约 7.3 MiB，结束后为零。回放阶段物理耗时读数为零，原计时与里程不变，页面错误与警告记录为空。成功／围堵的流程通过临时结束入口核验，摩托自然受撞翻覆也完成回看；未完成完整 20 公里、最高警力、直升机事件、所有碎片和减少动态效果的实驾。核验入口与人工标记未纳入正式代码。
